# AE UI Audio Editor Family Implementation Plan

**Goal:** 将 Audio Explorer、Audio Editor、音频工程创建、转换、合并、对白事件合并、波形与音频设置迁移到已批准的设计变量和公共控件，同时保持加载、播放、导出、编辑、编译、取消和文件写入行为不变。

**Authorization:** 用户已授权 Phase 1–7 连续本地实施、自动化视觉验证和本地提交；本批不推送、不创建 PR、不发布。

## Scope

- 迁移 `Editors/Audio` 下 12 个用户可见 XAML 界面及代码创建的 `MultiSelectTreeView` 样式消费者。
- 添加音频家族结构门禁和真实 WPF 四主题图库。
- 更新 UI 迁移清单；不修改音频格式、Wwise 数据、播放、转换、合并或编译算法。

## Behavior Contract

- Audio Explorer 的语言筛选、加载、搜索、树选择、播放、停止和四种导出入口保持不变。
- Audio Editor 的工程加载、新建、保存、编译、取消、快捷键、表格编辑、设置和波形交互保持不变。
- 工程创建、转换、工程合并和对白事件合并继续使用现有 ViewModel、命令、校验、取消与关闭生命周期。
- 表格与树继续保留多选、虚拟化、上下文菜单、拖放和键盘焦点；忙碌状态继续阻止重复操作。
- 不新增远程能力，不改变输出路径、文件名或覆盖策略。

## Execution

1. 建立 12 个 XAML 和代码控件消费者的覆盖门禁，先确认旧资源与硬编码颜色会失败。
2. 用 `AeBrush`、`AeFont`、`AeButton`、`AeInput`、`AeTree`、`AeList`、`AeTable`、`AeProgress` 和语义表面迁移界面。
3. 为主音频工作区、Audio Explorer、设置、工程创建、转换、工程合并、对白合并及忙碌状态建立真实 WPF 图库。
4. 在 100%、125%、150% 与四个要求主题下捕获并逐张检查文字、控件、表格、树、波形、遮罩和危险/取消操作层级。
5. 运行音频行为、可靠性、存储、播放、转换、合并和 UI 门禁，随后执行完整 Release 构建、完整测试和 `git diff --check`。

## Exit Gate

- 12 个音频 XAML 不再依赖旧主题画刷或硬编码主题色；所有主要交互控件使用公共控件层。
- 三档缩放和四主题下无裁切、重叠、低对比、错误滚动条或失焦状态。
- 音频真实文件与取消/失败路径的现有测试全部通过。
- 完整 Release 门禁通过并完成本地提交；不推送、不发布。
