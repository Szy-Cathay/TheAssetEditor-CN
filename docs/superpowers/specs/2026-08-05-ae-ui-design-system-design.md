# AE 国区版 UI 设计系统与渐进式重构设计

## 1. 结论

AE 国区版将进行覆盖全产品的视觉重构，但不进行一次性全量重写。实施方式是：先建立统一设计变量和公共控件家族，再按主窗口、公共流程、Pack/Git 工作区和编辑器模块逐批迁移。

目标视觉语言是：

> Visual Studio 的专业工作台骨架，加上 Codex 克制、安静且有轻微反馈的表面语言。

正式实现保留 WPF、XAML、MVVM、现有 Binding、Command、快捷键、自动化标识和业务状态，不引入新的 UI 框架，不全局启用第三方控件模板。

## 2. 目标与非目标

### 2.1 目标

- 建立统一的颜色、字体、间距、圆角、控件高度、图标和动效变量。
- 为按钮、输入、导航、集合、菜单、反馈、进度和对话框建立完整控件家族。
- 将主窗口重构为中等偏紧凑的深色专业工作台。
- 让所有控件具备一致的默认、悬停、按下、焦点、禁用、选中和错误状态。
- 通过渐进迁移覆盖全部 AE 国区版界面，且每批都可单独验证和回退。
- 保持中文界面、高 DPI、键盘操作、高对比度和主题切换能力。

### 2.2 非目标

- 不把 WPF 更换为 WinUI、WebView 或其他 UI 技术。
- 不借视觉重构修改 Pack、Git、音频、模型或编辑器业务语义。
- 不同时重构 ViewModel、服务层或依赖注入结构，除非视觉实现无法避免且另行确认。
- 不加入没有真实逻辑支持的搜索框、进度、状态或按钮。
- 不把所有业务界面强行抽象到 `Shared.Ui`。
- 不在迁移过程中顺手删除未确认无消费者的旧样式。

## 3. 当前实现约束

当前应用是 `net10.0-windows` 的 WPF/XAML/MVVM 应用。主题入口位于 `AssetEditor/App.xaml`，颜色字典位于 `AssetEditor/Themes/ColourDictionaries/`，语义控件颜色位于 `AssetEditor/Themes/ControlColours.xaml`，主要控件模板集中在 `AssetEditor/Themes/Controls.xaml`。

必须保留以下边界：

- `Shared.Ui` 只能依赖 `Shared/` 内项目，不能反向依赖 `AssetEditor`、`Editors` 或具体业务编辑器。
- `Shared.Ui` 中的通用控件通过动态资源键消费应用主题；真实应用和 WPF 测试宿主都必须提供这些资源。
- Panuon 只保留当前有限用途，不合并其全局 `StyleDictionary Includes="All"`。
- 所有用户可见文本继续通过 `AssetEditor/Language_Cn.json` 提供。
- 当前设置中的主题和字体选择能力必须保留。

## 4. 已确认的视觉方向

### 4.1 工作台结构

主窗口使用以下固定骨架：

1. 顶部保留窗口标题和现有菜单入口。
2. 左侧使用约 34 DIP 的窄活动栏切换已有工作域。
3. 活动栏右侧使用可调宽度的内容侧栏展示资源树、Git 或对应工具内容。
4. 中间保留多标签编辑区。
5. 右侧属性区由具体编辑器按需提供，不增加永久占位的全局右栏。
6. 底部状态栏只显示真实应用、Pack、Git 和进度状态。

活动栏只能连接已经存在的功能。图标使用项目现有 Material Icons 图标家族，并同时提供中文 ToolTip、可见键盘焦点和 `AutomationProperties.Name`。生产代码不使用依赖字体基线的 Unicode 符号充当图标。

视觉样板中的“搜索文件或命令”只用于表达顶部空间关系。本设计不包含命令搜索功能；没有真实搜索逻辑时，正式主窗口不显示假搜索框。

### 4.2 密度与层级

- 总体密度：中等偏紧凑。
- 标签高度：24 DIP。
- 紧凑树、列表和菜单行：28 DIP。
- 标准输入与按钮：30 DIP。
- 34 DIP 只用于少量顶层或空状态主操作，主按钮样式本身不自动增高。
- 工作区主要依靠对齐、文字层级、表面亮度和 1 DIP 边框分组。
- 页面不使用满屏卡片、玻璃、霓虹、大面积阴影或过度胶囊化。

## 5. 设计变量层

业务页面和公共控件只引用语义资源，不直接写具体颜色、字号、间距、圆角或动画时长。

### 5.1 深色石墨基线

| 角色 | 色值 | 用途 |
|---|---:|---|
| Canvas | `#151719` | 应用与编辑器最底层背景 |
| Surface 1 | `#1B1E21` | 侧栏、工具区域 |
| Surface 2 | `#212529` | 输入、标签活动表面 |
| Surface 3 | `#282D32` | 按钮、选中前景表面 |
| Hover | `#30363C` | 普通悬停 |
| Border | `#343A40` | 默认分隔与边框 |
| Strong Border | `#464E56` | 输入、弹层等较强边界 |
| Text Primary | `#E4E7E9` | 主要文字 |
| Text Secondary | `#B0B6BC` | 普通说明与控件文字 |
| Text Muted | `#858D95` | 辅助信息 |
| Accent | `#64A9E2` | 焦点、选中、主操作 |
| Accent Hover | `#75B5E8` | 强调色悬停 |
| Accent Soft | `#263A4B` | 低强度选中背景 |
| Success | `#72BC91` | 成功状态 |
| Warning | `#E2B45F` | 警告和未保存状态 |
| Danger | `#E17979` | 错误和危险操作 |

在深色基线上，主要文字、次要文字、辅助文字、强调色及三种语义状态与对应背景均达到普通文字所需的对比度。状态仍必须同时使用图标、文字或形状，不能只依靠颜色。

现有主题切换不能因新增语义键而失效。在任何新控件开始消费新键之前，所有现有主题都必须能解析完整语义资源。首轮视觉精调以深色石墨基线为准，浅色、高对比度及其他色板复用相同控件结构并单独校准颜色。

### 5.2 字体角色

默认字体组合为：

- 英文与数字：`Segoe UI Variable`，不可用时回退 `Segoe UI`。
- 中文：`Microsoft YaHei UI`。
- 路径、资源 ID、数值和日志：`Cascadia Mono`，不可用时回退 `Consolas`。

| 角色 | 大小 | 字重 | 用途 |
|---|---:|---|---|
| Page Title | 20 DIP | SemiBold | 页面级标题 |
| Section Title | 13 DIP | SemiBold | 分区标题 |
| Body / Control | 12 DIP | Normal | 正文和普通控件 |
| Label | 11 DIP | SemiBold | 字段标签 |
| Caption | 11 DIP | Normal | 时间、说明和辅助信息 |
| Technical | 11 DIP | Normal | 路径、ID、数值和日志 |

用户选择阿里普惠体或 HarmonyOS Sans 时，只替换字体家族和对应可用字重，不改变上述角色、字号和布局尺度。字体即时预览继续遵守“取消时恢复、保存后持久化”的设置事务边界。

### 5.3 间距、圆角与层级

- 间距只使用 4、8、12、16、24、32 DIP。
- 标签和紧凑行使用 3 DIP 圆角。
- 输入、按钮和小型选择面使用 4 DIP 圆角。
- 面板和菜单使用 6 DIP 圆角。
- 弹层和模态窗口最多使用 7 DIP 圆角。
- 大面积工作区不投影；阴影只用于弹层和模态窗口。
- WPF 中不在大型或持续变化表面使用高成本 `DropShadowEffect`。

### 5.4 动效标尺

| 场景 | 时长 | 允许变化 |
|---|---:|---|
| 按下反馈 | 70 ms | 颜色、最多 2% 缩放 |
| 悬停反馈 | 120 ms | 颜色、透明度 |
| 选中变化 | 140 ms | 颜色、指示线、透明度 |
| 弹层与提示 | 160 ms | 透明度、最多 2 DIP 位移 |

不动画 `Width`、`Height`、`Margin` 等布局属性。系统关闭客户端动画或处于高对比度等不适合动效的环境时，关闭入场和位移动画；真实不确定进度指示除外。

## 6. 公共控件层

### 6.1 控件家族

公共控件层至少覆盖：

- 主按钮、普通按钮、安静按钮和危险按钮；
- 文本输入、数值输入、选择器、复选框、单选框、开关和校验消息；
- 活动栏、标签页、树、列表、表格和空状态；
- 菜单、上下文菜单、ToolTip 和快捷键提示；
- 成功、警告、错误、未保存和加载状态；
- 确认框、标准对话框、弹层和真实进度；
- 滚动条、分隔条、焦点框和高对比度状态。

每个可交互控件必须覆盖：默认、悬停、按下、键盘焦点、禁用、选中或选中关闭、校验错误，以及控件支持的空和加载状态。

### 6.2 已确认的对齐规则

- 树节点的展开箭头使用固定尺寸矢量图标和独立居中容器，不使用字体字符。
- 展开箭头在完整行高中垂直居中，不能依赖文字基线。
- 成功、警告和错误通知图标相对整条通知内容垂直居中，不能只对齐第一行标题。
- 所有图标按钮和状态图标使用明确的图标盒尺寸，再在盒内居中矢量图标。
- 标签、字段、图标和数值按可见基线对齐，而不是只依赖默认控件 Padding。

### 6.3 资源组织

逻辑资源顺序为：

1. 主题颜色字典；
2. 语义 Brush 与文字颜色；
3. 字体、间距、几何和动效变量；
4. 按钮、输入、导航、集合、反馈和窗口等控件家族；
5. 具体窗口或页面的少量业务布局样式。

`AssetEditor/Themes/Controls.xaml` 按控件家族逐步拆分，迁移时保持资源键和合并顺序兼容。新样式先使用明确的键供已迁移界面选择；未迁移界面继续使用旧隐式样式。只有覆盖和状态验证完成后，才允许让旧隐式样式转接到新基类。

## 7. 行为与数据边界

视觉重构不得改变以下事实：

- 编辑器内存中的未保存编辑、文件夹工程磁盘工作树、Git 暂存区和提交历史继续严格分离。
- `Stage` 仍只选择提交内容，不能表现为 `Stash`。
- 成功、失败、加载、空状态和进度必须来自真实 ViewModel 或服务状态。
- 未知总量继续使用不确定进度，不通过动画伪造百分比。
- 只有真实命令可用时才显示对应操作；不放置无效占位按钮。
- 现有命令、访问键、快捷键、自动化名称和关闭流程必须保留。

## 8. 分批迁移

### 批次 1：设计系统基础

- 建立语义颜色、字体、间距、几何和动效资源。
- 建立新公共控件家族的基础状态。
- 保留旧隐式样式，不改变业务窗口结构。
- 确保所有现有主题能解析新资源键。

### 批次 2：主窗口样板

- 迁移主窗口、菜单栏、活动栏、资源侧栏、编辑器标签和状态栏。
- 活动栏只连接现有资源、Git 和工具入口。
- 验证现有编辑器创建、切换、关闭、拖动和未保存状态。

### 批次 3：公共流程界面

- 迁移设置、标准对话框、确认框、错误提示和真实进度界面。
- 统一设置预览、取消恢复和保存持久化状态。

### 批次 4：Pack 与 Git 工作区

- 迁移文件树、工作树、Git 管理、提交历史、分支和上下文菜单。
- 保持内存、磁盘、暂存和历史语义不变。

### 批次 5：编辑器模块

- 按音频、模型与 Kitbash、动画、元数据及其他编辑器家族逐批迁移。
- 每批只修改与目标模块直接相关的视觉和布局。

### 批次 6：主题兼容与旧样式清理

- 精调浅色、高对比度及其他现有色板。
- 建立旧样式消费者清单。
- 只有确认无消费者并通过完整验证后，才单独删除旧资源。

每个实施批次使用独立 `codex/` 分支。提交、推送、创建 PR 和合并 PR 分别取得授权。

## 9. 验收门槛

### 9.1 自动验证

每批至少执行：

- 受影响的 WPF、ViewModel 和架构测试；
- 受影响项目的 Release 构建；
- `git diff --check`；
- 新资源键在深色、浅色和高对比度字典中的解析检查；
- 涉及公共 UI 边界时运行 `SharedUiArchitectureTests`；
- 涉及主题和 WPF 实例化时使用 `WpfTestApplicationHost`。

跨公共控件或多模块的批次在阶段完成前执行完整 Release 构建和完整测试。修改测试后必须先重新构建测试项目，不能用旧程序集的 `--no-build` 结果判断新代码。

### 9.2 视觉验证

每批人工视觉验收覆盖：

- 正常和窄窗口；
- 100%、125% 和 150% 缩放；
- 深色、浅色和高对比度；
- 鼠标、键盘和可见焦点；
- 默认、悬停、按下、禁用、选中和错误状态；
- 加载、空、失败、重试和未保存状态；
- 中文截断、文字基线、图标居中、滚动条和弹层位置。

自动化测试不能证明视觉正确。未经明确授权不控制用户桌面，由用户完成最终视觉验收并反馈截图或标注。

## 10. 风险与回退

### 10.1 主要风险

- 修改隐式样式会同时影响未迁移窗口。
- 拆分资源字典时改变合并顺序会导致键缺失或外观覆盖。
- 字体变化会改变中文宽度、行高和高 DPI 下的截断行为。
- 动画若作用于布局属性会造成 WPF 卡顿和内容抖动。
- 只在深色主题观察会遗漏浅色、高对比度和独立视图测试问题。

### 10.2 回退策略

- 新控件样式先按键选择使用，避免立即替换所有隐式样式。
- 每批保持范围独立，不夹带业务重构。
- 迁移前记录目标窗口的当前行为和状态覆盖。
- 若视觉或行为门禁失败，回退该批界面对新样式的引用，不删除旧样式。
- 旧资源直到完整消费者清单归零后才删除。

## 11. 完成标准

整体 UI 重构只有在以下条件全部满足后才算完成：

- 所有用户可见窗口和主要编辑器已迁移到统一设计系统；
- 公共控件所有必要交互状态完整；
- 深色、浅色和高对比度均可读且无资源缺失；
- 现有业务命令、键盘操作、自动化标识和状态语义保持不变；
- Release 构建、完整测试、架构门禁和差异检查通过；
- 用户完成实际窗口的视觉验收；
- 旧样式清理有完整消费者证据，不依赖猜测或仅凭文件名判断。

## 12. 最终长期规范收口

所有实施批次完成且用户确认实际界面没有问题后，才创建长期 UI 规范 `docs/ui-design-system.md`。该规范必须以最终代码和用户验收结果为事实来源，不能直接复制仍处于计划阶段的内容。

长期规范至少包含：

- 已落地的颜色、字体、间距、几何、图标和动效变量；
- 主窗口、公共控件和业务页面的稳定布局规则；
- 完整交互状态、键盘、高 DPI、高对比度和中文本地化要求；
- 加载、进度、错误、未保存和危险操作的呈现规则；
- WPF 资源组织、`Shared.Ui` 依赖边界和主题测试入口；
- 新功能 UI 的设计、实现和视觉验收清单；
- 明确禁止的外观、假状态和架构做法。

规范完成并由用户确认后：

1. 在 `docs/README.md` 中把所有 UI 设计、实现和审查任务路由到 `docs/ui-design-system.md`。
2. 在根 `AGENTS.md` 中加入强制规则：以后 Codex 新增或修改用户界面时，必须先读取并遵循该规范。
3. 建立本次 UI 重构生成文档的完整清单，用长期规范取代本次一次性设计规格和实施计划，并删除相应索引。
4. 保留 `docs/architecture.md`、`docs/folder-project-version-control.md` 等非视觉契约文档；不得以“取代 UI 文档”为由删除架构、业务语义、测试或来源说明。
5. 删除旧 UI 文档前逐项核对其稳定规则已经进入长期规范，不能只按文件名批量删除。

长期规范的创建、旧 UI 文档删除和规则入口更新属于最终独立批次。在所有实施和用户验收完成前，不提前执行该批次。
